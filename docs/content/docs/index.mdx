## What is Sandcastle?

Sandcastle is a TypeScript CLI tool that orchestrates AI coding agents inside isolated sandbox environments. It manages the full lifecycle of running an agent against your codebase: syncing code into a sandbox, invoking the agent, and syncing changes back.

## Key Concepts

- **Sandbox** -- An isolated environment (Docker container or local directory) where an agent executes code
- **Host** -- Your machine where Sandcastle runs and the real git repo lives
- **Agent** -- The AI coding tool invoked inside the sandbox (e.g. Claude Code)
- **Iteration** -- A single invocation of the agent, producing at most one commit

## Quick Start

### 1. Install

```bash
npm install -g @yogioo/sandcastle
```

The global install provides the primary `sandcastle` command. If you do not
want a global install, use `npx @yogioo/sandcastle` as a fallback.

### 2. Initialize

Run `sandcastle init [path]` in your repository to scaffold the workflow and
state directory in the per-user cache. The path is optional and defaults to
the current working directory:

```bash
sandcastle init
```

On Windows this defaults to `%LOCALAPPDATA%/Sandcastle/projects/<project-id>/.sandcastle/`.
The command prints the actual directory and entry-file paths and writes a
project manifest there. Use `--state-dir` to select an explicit state
directory; the CLI never falls back to a repository-local `.sandcastle`.

### 3. Run

```bash
sandcastle
```

When the current directory is a registered project, Sandcastle runs it
directly. Otherwise it offers a compact project selector; you can also run a
specific project with `sandcastle <path>`. The generated entry file is launched
internally. Use `npx @yogioo/sandcastle` in place of `sandcastle` when using
the fallback installation path.
