## State Directory

`sandcastle init` stores the `.sandcastle/` directory in the per-user project
cache by default. On Windows this is
`%LOCALAPPDATA%/Sandcastle/projects/<project-id>/.sandcastle/`. Pass
`--state-dir <directory>` to select an explicit state directory. The CLI
requires a valid external project manifest and never falls back to a
repository-local `.sandcastle/`.

- `main.ts` / `main.mts` -- The workflow entry point
- `Dockerfile` -- Defines the sandbox environment
- `prompt.md` -- The prompt sent to the agent each iteration
- `.env` -- Environment variables for the sandbox; `init` creates it with
  required keys commented out so you can fill them in
- `logs/`, `worktrees/`, and `patches/` -- Runtime artifacts

## Prompt

The `prompt.md` file is the instruction text passed to the agent at the start of each iteration. It supports:

- **Prompt arguments** -- `{{KEY}}` placeholders replaced with values from `promptArgs`
- **Shell expressions** -- `` !`command` `` markers that evaluate shell commands inside the sandbox

## Environment Variables

Sandcastle reads the state directory's `.env` file and falls back to
`process.env` only for keys declared in that file. Commented lines are ignored,
so uncomment a key (even with an empty value) to opt into the process.env
fallback.
